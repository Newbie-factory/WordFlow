# FSRS-6 domain scheduler

WordFlow's domain scheduler implements FSRS-6 without learning-step queues, fuzzing, persistence, or UI behavior. The product exposes only `Again = 1`, `Hard = 2`, and `Good = 3`; Slash is a separate business action and is not an FSRS rating.

## Pinned algorithm reference

The formulas and frozen vectors were independently generated from the official Open Spaced Repetition project:

- repository: `https://github.com/open-spaced-repetition/py-fsrs`
- release: `v6.3.0`
- commit: `854a51496993d088175f6d7da0bbfaa414034c61`
- reference module: `fsrs/scheduler.py`
- reference configuration: `Scheduler(learning_steps=(), relearning_steps=(), enable_fuzzing=False)`

The upstream public wrapper and WordFlow's approved time contract are deliberately distinct:

- `Scheduler.review_card` and `Scheduler.get_card_retrievability` use Python `timedelta.days`, which truncates to an integer number of elapsed days. Thus the public wrapper observes retrievability `1.0` after ten minutes and, at 10.5 days, uses 10 days and produces Good stability `25.10872016830931`.
- WordFlow's approved contract requires continuous UTC `TotalDays`. The independent generator therefore uses `(reviewed_at - last_review).total_seconds() / 86400` and supplies that value to the pinned formula helpers. This produces retrievability `0.9995456304854935` after ten minutes and Good stability `25.63120446574721` at 10.5 days.

The checked-in [`generate_fsrs6_vectors.py`](generate_fsrs6_vectors.py) refuses any checkout except the full pinned commit, imports that checkout, and evaluates in upstream order: `_initial_difficulty`/`_initial_stability` for new state; the forgetting curve from pinned `_FACTOR`/`_DECAY`; `_short_term_stability` for elapsed `< 1`; otherwise `_next_stability` with pre-review difficulty and retrievability; then `_next_difficulty`; finally `_next_interval`. The frozen output is [`fsrs6-vectors.json`](fsrs6-vectors.json), SHA-256 `A26EF98A1939B0E62877EEF1756FBFE8CA4609F81BFDD84A325C7F182CD74651`. It includes the public integer-day comparison so the adaptation cannot be mistaken for public-wrapper output.

## Formula correspondence

Let `w[i]` denote parameter `i`, `G` the numeric rating, `D` difficulty, `S` stability in days, `R` retrievability, and `t` elapsed days.

- Initial stability: `S0(G) = w[G - 1]`.
- Initial difficulty: `D0(G) = w[4] - exp(w[5] * (G - 1)) + 1`, clamped to `[1, 10]`.
- Forgetting curve: `R(t,S) = (1 + factor * t / S)^(-w[20])`, where `factor = 0.9^(-1 / w[20]) - 1`. Consequently `R(S,S) = 0.9`; parameter 20 is trainable.
- Same-day stability (`t < 1 day`): `S' = S * exp(w[17] * (G - 3 + w[18])) * S^(-w[19])`. For Good, the multiplier is bounded below by one, matching the reference's Good/Easy guard while WordFlow has no Easy action.
- Difficulty update: reference linear damping and mean reversion are used, followed by `[1, 10]` clamping.
- Long-term recall and forgetting updates correspond directly to `_next_recall_stability` and `_next_forget_stability` at the pinned commit. The long-term formula receives the pre-review difficulty, as the reference does; difficulty is updated separately for the resulting state.

## Time and interval contract

- Every persisted/result instant is normalized with `ToUniversalTime()` and returned at offset `+00:00`.
- Elapsed time is continuous absolute time: `(reviewedAtUtc - lastReviewAtUtc).TotalDays`. It is not a calendar-date difference and is culture/time-zone independent.
- A review or retrievability query before the last-review instant is rejected.
- Elapsed time strictly below 24 hours uses the FSRS-6 same-day formula; exactly 24 hours uses the long-term formula.
- Desired retention must be finite and in the inclusive product range `[0.85, 0.95]`.
- The continuous optimal interval is rounded only at the scheduling boundary to a whole number of days using IEEE/.NET round-to-nearest, ties-to-even, the same midpoint rule used by Python 3 `round` in the pinned reference. A scheduled interval has a minimum of one day. WordFlow applies no random fuzz and no maximum-interval product cap in this pure domain service; an interval that cannot be represented by `TimeSpan` or `DateTimeOffset` is rejected.
- States and parameter inputs reject non-finite values. Stability is positive (with FSRS minimum `0.001`) and difficulty remains in `[1, 10]`.

## Frozen vector coverage

The golden suite freezes initial Again/Hard/Good, a ten-minute same-day Hard review, an exact-24-hour transition, a 10.5-day delayed Good review, a 30-day Again lapse, retention settings 0.85/0.90/0.95, and two equivalent instants spanning local/UTC calendar dates. The invariant suite runs 10,000 deterministic histories and checks finite states/probabilities, positive intervals, monotonic due instants, difficulty range, UTC normalization, the `R(S)=0.9` identity, and retention ordering.

## Safe local parameter optimization

WordFlow's `FsrsParameterOptimizer` is a bounded deterministic C# coordinate search. It runs in-process without Python, network, database, or WPF dependencies. The default fixed seed is `0x5F3759DF`; the seed determines the repeatable direction order. Four search rounds evaluate both directions for each of the 21 parameters with a decreasing step. Nonzero coordinates use multiplicative steps; a coordinate at an official zero lower bound uses a deterministic positive additive step so it remains searchable. Every candidate is constructed through `FsrsParameters`, so the Task 4 official bounds remain the single enforced parameter domain. Cancellation is checked during duplicate discovery, filtering, sorting/grouping/partitioning, every history evaluation, and every candidate evaluation. `IProgress<OptimizationProgress>` reports plain progress values without any dispatcher reference; the caller chooses how those reports are marshalled.

Eligibility requires at least 400 valid input reviews. Validity is deterministic in the supplied event order:

- the command and card identifiers are nonblank;
- the event is neither undone nor inverse;
- the event kind is `Rating`, never Slash or another business event;
- the numeric rating is exactly Again (`1`), Hard (`2`), or Good (`3`);
- every occurrence of a duplicated command ID is excluded; and
- a card's accepted review timestamp is strictly later than its previous accepted timestamp.

Events later than `DateTimeOffset.MaxValue - 1 day` are also rejected as schedule-impossible because Task 4 guarantees a minimum one-day due interval. Every result reports input, valid, and filtered event counts separately.

The optimizer then orders valid samples by their normalized UTC instants. The chronological split boundary is the 80th percentile event instant. The split unit is a whole card history: a history wholly before the boundary is training data, a history wholly at/after the boundary is validation data, and a card spanning the boundary is excluded from both objectives. This conservative gap prevents both future-to-past leakage and per-card identity/history leakage when card histories interleave. The eligibility count remains the count before this split; optimization is `NotEligible` if either objective partition cannot be evaluated.

For each partition, a new card's first rating initializes its state but is not a supervised observation because no pre-review retrievability exists. Each subsequent rating uses the pinned scheduler's continuous UTC retrievability immediately before the review. Again is binary failure; Hard and Good are binary recall success. The objective is mean Bernoulli negative log likelihood:

```text
L = mean(-y log(R) - (1-y) log(1-R))
```

Only the logarithm input is clamped to `[1e-15, 1-1e-15]`; the FSRS prediction and state update are not clamped or otherwise altered. Baseline and candidate use the identical evaluator. Results report training/validation event counts and supervised observation counts separately. Empty objectives produce `NotEligible`; an unusable baseline produces `InvalidData`; unusable trial candidates are skipped and an unusable final candidate produces `BaselineRetained` with an audit reason. A training-selected candidate is activated as an optimization result only when its validation loss is no greater than the baseline validation loss plus `1e-12`; otherwise the baseline is retained. This held-out rule is the overfitting guard.

The independent optimization fixture is [`fsrs6-optimizer-fixture.json`](fsrs6-optimizer-fixture.json). It pins two continuous-time pre-review probabilities and their binary recall log loss. Reproduce it only for development/provenance checks:

```powershell
  --output $env:TEMP\fsrs6-optimizer-fixture.json
git diff --no-index -- docs\algorithms\fsrs6-optimizer-fixture.json $env:TEMP\fsrs6-optimizer-fixture.json
```

At the application boundary, every run appends a snapshot containing algorithm version, exact optimizer status, source and result parameter sets, input/valid/filtered and partition event/observation counts, sample and loss metrics, rejection reason, UTC creation time, and activation state. Accepted results are first stored as `PendingPreview`; only a successful due-date preview transitions them to `ReadyForActivation`. Preview exceptions/cancellation are audited as `PreviewFailed`, and a failed ready-state store transition leaves the existing pending snapshot nonactivatable. Activation appends a settings event; it changes only the active parameter set consulted by later scheduling computations. No API exists in this use case to rewrite ratings or mass-reschedule cards. Restore accepts a prior activation-event ID—not a snapshot ID or caller-crafted parameter set—and appends a new activation preserving the source activation ID. The persistence port is intentionally focused and has no Task 7 SQLite implementation.
