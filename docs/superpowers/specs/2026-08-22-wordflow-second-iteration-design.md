# WordFlow Windows 第二轮用户迭代设计

日期：2026-08-22  
目标平台：Windows 10 22H2、Windows 11  
运行约束：完全离线、单实例、本机 SQLite、两款图标对应两个功能相同的 EXE

## 1. 目标与已确认决策

本轮在现有 WordFlow 桌面端基础上完成六类升级：双图标发布、流畅且范围更宽的图片皮肤透明度、总斩词目标、可跨重启与跨日续学的每日队列及六个月历史、可配置的强力置顶、1–10 次新词自动复读。

用户已确认以下关键口径：

- 横向 `WordFlow` 图片制作成方形图标，以最方便、清晰的方式居中排版。
- “始终置顶”开启后采用不抢焦点的周期性强力置顶；隐藏时停止。
- 跨日不累加压力：遗留任务优先，再补齐到当天两个目标；例如新词目标 40，昨日剩余 27，则今日用 27 个遗留词加 13 个新词组成 40 个新词任务，而不是 67 个。
- 每日队列使用 SQLite 持久化；当天重新启动必须继续显示未提交的当前单词。
- 当天因 `Again` 产生的重学词作为额外优先项，不占新词或复习目标额度。
- 总目标只按“斩”计算，认识或完成复习不等于总目标完成。

## 2. 设计方向

### 2.1 使用场景

用户在 Windows 桌面工作期间长期保留一个轻量悬浮学习卡，通过全局快捷键快速评分。控制中心承担计划、历史、外观、发音和数据管理。所有学习数据、主题图片和设置只保存在本机。

### 2.2 视觉基调

沿用当前克制的浅色卡片式设计和圆角系统，不重做信息架构。第二轮新增内容优先采用紧凑进度条、低噪声日历热力格和原生可访问控件，避免给悬浮卡增加新的视觉负担。

### 2.3 唯一视觉记忆点

“总斩词进度 + 六个月完成日历”作为控制中心的长期反馈核心：不使用焦虑式红色，不制造惩罚感，但让长期积累一眼可见。

## 3. 双图标、双 EXE 发布

### 3.1 源图片

- `D:\baicizhan\icon\3bc1eaac-1f64-4757-abd3-8a14b846ce80.png`
- `D:\baicizhan\icon\QQ_1787369551829.png`

原图只读保留。构建资产复制到仓库的图标资产目录，派生 ICO 不覆盖原图。

### 3.2 图标生成

- 照片图标：以中心为锚点裁成正方形，保持主体完整。
- WordFlow 图标：放入透明正方形画布，等比缩放并居中，保留完整字样和安全留白。
- 两个 ICO 均包含 16、24、32、48、64、128、256 像素帧，使用高质量缩放。
- 图标写入 EXE 资源，托盘图标从当前 EXE 资源读取，保证桌面、任务管理器和托盘一致。

### 3.3 交付物

- `WordFlow-Photo.exe`
- `WordFlow-Classic.exe`

两个 EXE 使用同一代码、同一数据目录、同一单实例互斥标识和同一 `%LOCALAPPDATA%\WordFlow` 用户数据。任意一个已运行时，启动另一个只激活已有实例，不会产生两套进度。

## 4. 图片皮肤与透明度

### 4.1 格式与安全

主题服务从 PNG 专用模型升级为通用图片模型，支持 `.png`、`.jpg`、`.jpeg`，扩展名大小写不敏感。导入时同时验证：

- 文件签名与可解码格式一致；
- 文件存在，大小不超过 20 MB；
- 宽高均不超过 8192 像素；
- 解码成功且至少包含一帧；
- 导入副本位于本机皮肤目录，设置只保存安全目录中的绝对路径。

失败导入不替换当前主题。旧的 `theme.png_path` 设置自动迁移或兼容读取，已有 PNG 皮肤无需重新选择。

### 4.2 流畅预览

当前卡顿的根因是每次滑块变化都会重新解码图片并触发 SQLite 写入。本轮拆分为两条路径：

1. **实时预览路径**：图片在路径变化时仅解码一次，缓存为冻结的 WPF 图像资源；滑块拖动只修改图层数值，不触发文件读取或数据库写入。
2. **延迟持久化路径**：透明度变化经过约 250 ms 防抖，只保存最后一个值；拖动结束、窗口关闭和程序退出时执行最终刷新。

控制中心和悬浮卡共享同一个主题状态。任意一处拖动，另一处滑块和图片立即同步。

### 4.3 范围与视觉映射

- 滑块范围：0%–100%，不吸附刻度。
- `IsMoveToPointEnabled=True`，点击滑轨时滑块立即移动到指针位置。
- 拖动时 Thumb 持续跟随鼠标，不因后台保存或图片解码阻塞 UI 线程。
- 图片不透明度随滑块从 0.00 线性变化到 1.00。
- 阅读保护层随图片强度从约 0.88 反向减弱到约 0.12；正文内容始终保持 1.00 不透明度。
- 图片保持用户此前要求的四角强制铺满方式，即 `Stretch=Fill`。

启动顺序保持为“读取主题设置 → 创建悬浮卡 → 应用缓存图片与透明度”，从而恢复上次图片、透明度和滑块位置。

## 5. 每日学习队列、恢复与跨日补齐

### 5.1 新的持久化模型

新增版本化 SQLite 结构：

**daily_sessions**

- `local_day`：用户本地日期，主键；
- `configured_new_target`、`configured_review_target`：当天创建时的设置值；
- `effective_new_target`、`effective_review_target`：结合实际可用词计算后的有效目标；
- `completed_at`、`created_at`、`updated_at`；
- 版本与完整性字段。

**daily_queue_items**

- `item_id`；
- `local_day`、`ordinal`；
- `card_id`；
- `kind`：`New`、`Review`、`Relearning`；
- `origin_day`：遗留任务的原始日期；
- `status`：`Pending`、`Completed`、`Slashed`；
- `completed_event_id`、`created_at`、`completed_at`。

索引覆盖“按日期和状态取下一项”“按卡片查未完成项”“读取 183 天历史”。数据库迁移是幂等的，升级不改变已有学习事件和 FSRS 状态。

### 5.2 当日创建与恢复

- 使用 `TimeProvider.GetLocalNow()` 的本地日期，避免 UTC 跨日偏差。
- 当日会话不存在时，在一个事务中创建会话与有序队列。
- 当日会话存在时，不重算队列；直接返回序号最小的待处理项。因此用户完成 13 个后退出，再打开仍显示第 14 个。
- 当前卡未提交时不移动指针；崩溃或强制结束后重新启动仍显示同一词。
- 评分/斩词学习事件与队列项完成状态在同一 SQLite 事务中提交，避免“学习记录已写但队列未前进”或反向不一致。

### 5.3 跨日补齐

新一天首次建队列时：

1. 按原队列顺序读取历史未完成项；
2. 新词遗留优先占用今日新词目标，复习遗留优先占用今日复习目标；
3. 各类别不足目标时，再从今日 FSRS 到期词和新词候选中补齐；
4. 遗留数量超过今日目标时，只取今日目标数量，其余保留在有序积压中供后续日期继续承接；
5. 临近词库结束或当日到期复习不足时，有效目标取实际可用数量，避免出现永远无法完成的计划。

### 5.4 重学项与完成条件

- `Again` 导致当天再次到期时，加入或激活 `Relearning` 项，优先级高于普通复习和新词，不占两项目标。
- 切换到新词会取消上一词仍在进行的自动语音。
- 当天有效新词、复习目标均完成，且已到期的重学项清空后，记录 `completed_at`。
- `Slash` 同时完成当前队列项并更新全局已斩进度。
- 撤销操作同步恢复对应队列项与会话完成状态。

## 6. 六个月完成历史与总目标

### 6.1 总目标进度

控制中心“今日学习”页显示：

- 已斩词数；
- 本地可学习头词总数；
- `已斩 / 总词汇`；
- 百分比，至少保留两位有效小数以便早期进度可见；
- 一条低噪声主进度条。

总目标完成率只统计当前处于已斩状态的不同词条。取消斩后，已斩数和百分比立即下降。

### 6.2 最近六个月日历

读取今天及之前 182 天，共 183 个本地日期：

- 绿色勾选：当日会话完成；
- 浅橙：当日开始但未完成；
- 中性灰：当日没有会话/没有学习；
- 今日增加轮廓强调；
- 每格 Tooltip 显示日期、新词完成/目标、复习完成/目标和重学状态。

页面使用紧凑周网格，支持滚轮查看但不挤压顶部核心数据。颜色不是唯一信息载体，Tooltip 和自动化名称同时提供文字状态。

## 7. 悬浮卡精简

删除包含以下内容的整行：

- “专注当前词 · 提交后进入下一词”；
- 可见的“撤销 Ctrl+Z”按钮。

撤销命令、可配置快捷键和 `Ctrl+Z` 默认行为继续保留。删除该行后收紧卡片高度和按钮区间距，不留下空白占位。

## 8. 可配置强力置顶

### 8.1 设置

在“设置 → 悬浮卡与外观”增加“始终置顶”开关，默认开启并持久化到本机设置。此开关取代旧的“全屏时抑制定置顶”作为用户可见主策略；旧设置不会导致升级后意外关闭新功能。

### 8.2 行为

- 开启：窗口显示期间设置 WPF `Topmost`，并约每 500 ms 使用 `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)` 重新声明 Z 序；窗口显示、系统激活和失去激活时也立即重新声明。
- 关闭：停止定时器，调用 `HWND_NOTOPMOST`，关系词弹层同步降级。
- 隐藏、退出：停止守护，不创建后台抢层操作。
- 全程使用 `SWP_NOACTIVATE`，不抢键盘焦点、不把其他软件切到后台。

Windows 的独占全屏或更高权限进程可能绕过普通桌面 Z 序，因此产品文案使用“强力置顶”，不承诺突破操作系统安全边界。

## 9. 新词自动复读 1–10 次

- 设置位置：“设置 → 发音”。
- 新增整数设置 `pronunciation.autoplay_repeat_count`，范围 1–10，默认 1。
- 控制中心显示 1–10 次选择器，并说明它只影响切换新单词后的自动朗读。
- 自动朗读开启时，新卡出现后串行播放指定次数；每次等待前一次播放完成后再开始，不重叠。
- 切换下一词、暂停、隐藏、关闭自动朗读或退出时立即取消剩余次数。
- 手动点击单词或手动发音快捷键始终只读 1 次，避免用户一次点击触发长队列。
- 非法或损坏设置自动修复为 1，并写回安全值。

## 10. 错误处理与兼容性

- 所有设置读取失败均退回安全默认值并记录本地日志，不阻断学习。
- 每日队列事务失败时保留当前卡，不提前切换；界面显示可操作的本地错误。
- 主题防抖保存失败只提示一次，内存预览保持，下一次保存可重试。
- 图片文件丢失或损坏时回退默认皮肤，并保留学习数据。
- 两个 EXE 不复制用户数据库；升级前后的 SQLite 迁移保持向前兼容。
- 功能不引入网络客户端、账号、遥测或在线资源。

## 11. 测试与验收

### 11.1 自动测试

- 每日队列：首次建队、完成 13/40 后重启、跨日 27+13 补齐、遗留超过目标、设置变更、可用词不足、UTC/本地日期边界、Again 重学、Slash、Undo、事务故障恢复。
- 六个月历史：183 天边界、完成/未完成/无会话、Tooltip 数据、取消斩后的总目标回退。
- 图片皮肤：PNG/JPG/JPEG 大小写、签名伪造、损坏图片、超限图片、旧设置迁移、0%/100% 边界、启动恢复、防抖只保存最终值。
- 流畅度结构门禁：连续透明度变化不得重新解码图片；数据库写入次数被防抖合并。
- 置顶：开关持久化、隐藏时停止、关闭时 `NOTOPMOST`、开启时周期重申、弹层同步。
- 发音：1 次、10 次、非法值修复、串行不重叠、切词取消、手动仍为 1 次。
- 悬浮卡 XAML：目标文本行和可见撤销按钮不存在，快捷键命令仍存在。
- 发布：两个 EXE 的代码与数据清单一致，图标资源不同；分别可正常启动；双 EXE 同时启动时仍只有一个实例。

### 11.2 Windows 实际验证

- 100%、125%、150%、200% DPI 下拖动两个透明度滑块，Thumb 始终位于指针下，图片连续实时变化。
- 导入 PNG、JPG、JPEG 并重启，图片、透明度和滑块位置恢复。
- 用另一个 Topmost 测试窗口覆盖 WordFlow，确认强力置顶在一个守护周期内恢复；关闭开关后不再恢复。
- 模拟当天完成 13/40 后重启，显示第 14 个；推进系统日期后验证遗留优先和目标内补齐。
- 检查六个月日历、总斩词比例、取消斩后的即时变化。
- 使用空输出语音引擎验证 1–10 次序列，再用 Windows 本机英语声音进行听感验证。
- 使用资源查看器或系统属性确认两个 EXE 图标不同，功能入口和本地数据一致。

### 11.3 发布门禁

- 数据库迁移与词库完整性检查通过；
- Release 编译 0 error、0 warning；
- 全量自动测试 0 failure；
- 两个自包含 EXE 均通过普通启动与单实例冒烟；
- 记录两个 EXE 的 SHA-256、文件大小和图标来源；
- 不使用“绝对永远置顶”或“绝对无 Bug”等无法验证的表述。

## 12. 非目标

- 本轮不实现云同步、账号、跨设备学习进度或网络词典。
- 本轮不改变 FSRS-6 数学公式和现有历史评分。
- 本轮不把“认识”自动视为“斩”；斩词仍由用户明确触发。
- 本轮不承诺覆盖 Windows 安全桌面、UAC 提示或独占全屏的系统级最高层。
